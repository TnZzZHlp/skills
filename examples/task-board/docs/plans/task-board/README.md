## 概述

一个本地单用户浏览器应用，用于创建任务，并在“待办”“进行中”“已完成”三个状态之间跟踪进度。重启应用后，任务仍然保留。

本文的产品与技术决策均为虚构演示输入。下文的应用路径相对于示例工作区，均为拟新增路径，尚未创建。

### 接口与数据流

任务字段：服务端生成的 UUID `id`、去除首尾空白的 `title`、枚举 `status`，以及服务端生成的 UTC ISO-8601 时间 `createdAt`/`updatedAt`。标题处理后长度为 1–120 个 Unicode 码点。状态值为 `todo`、`in-progress`、`done`。

| 接口 | 输入 | 成功响应 |
| --- | --- | --- |
| POST /api/tasks | JSON 标题 | 201，返回新任务，初始状态为 todo |
| GET /api/tasks | 无 | 200，返回任务数组，按 createdAt、ID 依次升序 |
| PATCH /api/tasks/:id | JSON 状态 | 200，返回更新后的任务 |
| DELETE /api/tasks/:id | 任务 ID | 204，无响应体 |

UUID 格式错误、非法 JSON、未知输入字段、非法标题或不支持的状态返回 400。数据修改请求有请求体时必须使用 JSON。格式正确但不存在的任务 ID 返回 404。被拒绝的跨来源修改请求返回 403。意外存储错误返回通用 500，不暴露内部细节。错误结构为 `{ "error": { "code": "...", "message": "..." } }`。

浏览器使用相对 API URL。开发期间，拟使用 Vite 代理将请求转发到本地 API，不配置宽松的 CORS 策略。只有服务端确认成功后，才更新浏览器中的任务状态；修改失败不自动重试。

## 决策记录

以下决策由流程示例中的虚构用户接受，并非真实用户确认的生产需求。

| 编号 | 决策 | 理由 | 权衡 |
| --- | --- | --- | --- |
| D01 | React/Vite、Node.js/TypeScript、SQLite | 前后端使用同一语言，支持本地持久化 | 相比纯 IndexedDB 应用，组件更多 |
| D02 | 使用状态选择器，不做拖拽 | 交互更简单，便于键盘操作 | 缺少拖拽式直接操作 |
| D03 | 仅监听回环地址，并检查修改请求来源 | 明确限定本地部署场景 | 远程访问需要重新规划并加入身份认证 |
| D04 | 确认写入后再更新看板 | 避免误报成功和复杂回滚 | 请求期间需要显示等待状态 |

| 风险 | 影响 | 缓解措施 | 阶段 |
