## 目标与范围

提供四个任务接口，实现持久化，并明确处理输入和操作错误。不包含浏览器界面、账户、云部署，以及由阶段 003 负责的跨层自动化验证。

前置条件：真实实施需要单独授权。所有目标路径均为拟新增路径。

## 设计

| 路径 | 职责 |
| --- | --- |
| apps/api/src/main.ts | 组装服务器、服务和仓储，仅监听回环地址 |
| apps/api/src/tasks/schema.ts | 验证请求结构，序列化任务契约 |
| apps/api/src/tasks/service.ts | 执行标题和状态规则，协调仓储调用 |
| apps/api/src/tasks/repository.ts | 参数化任务查询和事务边界 |
| apps/api/src/tasks/routes.ts | 薄 HTTP 适配层，包含错误映射 |
| apps/api/src/database/ | 连接管理和幂等的初始迁移 |

SQLite 保存 ID、标题、状态、createdAt 和 updatedAt。通过数据库约束保证合法状态和非空字段；服务层按 Unicode 码点验证标题长度。UUID 和时间戳均在服务端生成。

严格遵循总计划的接口与错误契约。允许非浏览器客户端发送不含 Origin 的修改请求，但拒绝明确来自外部来源的请求；JSON 要求与回环监听仍然必须满足。不启用通配 CORS。

交付物：可运行的本地 API、初始数据库结构，以及运行时数据库路径配置说明。本阶段不交付 UI。
